# CloudFile Open Source And Commercialization Principles
# CloudFile 开源与商业化基本原则

[English home](../README.md) · [中文首页](../README.zh-CN.md)

**Open source first; Apache 2.0 preferred; upstream licenses respected; room for customer customization; sustainable development through professional services; contributions back to the community.**

**开源优先、Apache 2.0 优选、尊重上游许可、为客户定制保留空间、以专业服务支持持续发展，并积极回馈开源生态。**

## 1. Open Source First / 开源优先

CloudFile develops its general-purpose product in the open. Reusable capabilities and improvements belong in the public product so that users can deploy, use and adapt it under the applicable licenses. Customer needs help improve the shared product over time.

CloudFile 以开源方式发展通用产品。具有通用价值的能力与改进进入公开产品，让使用者能够按照适用许可证自主部署、使用和定制，并通过客户实际需求持续完善共享的产品能力。

## 2. Apache 2.0 Preferred / Apache 2.0 优选

New, independently developed CloudFile code prefers Apache 2.0 to support reuse, enterprise integration and downstream customization. Existing appropriate licenses, including MIT, can remain. The license and copyright notices of each component define its terms.

CloudFile 新增的独立自主开发代码优选 Apache 2.0，支持复用、企业集成和下游定制。已有合理许可证，包括 MIT，可以继续保留。具体许可与版权声明以各组件为准。

## 3. Respect Upstream Licenses / 尊重上游许可

CloudFile preserves the licenses of Seafile, Filestash and other upstream projects, including AGPLv3-covered code. The Apache preference does not relicense upstream-derived work. Architectural separation is considered when actual customer customization needs justify it, with attention to code provenance and technical coupling; changing a repository, plugin or deployment boundary does not itself change license obligations.

CloudFile 保留 Seafile、Filestash 等上游项目的许可证，包括受 AGPLv3 覆盖的代码。Apache 优选原则不意味着对上游派生代码重新许可。只有实际客户定制需求需要时，才结合代码来源和技术耦合评估架构拆分；改变仓库、插件或部署边界本身不改变许可义务。

## 4. Leave Room For Customer Customization / 为客户定制保留空间

CloudFile supports enterprise APIs and integrations that let customers connect their own identity systems, business processes and applications. Customer-specific implementations can be maintained separately, with ownership, delivery and disclosure terms determined by applicable licenses and contracts. General-purpose improvements should return to the public product where rights permit.

CloudFile 通过企业 API 和集成能力，支持客户对接自身身份体系、业务流程和应用。客户专属实现可以独立维护，其权属、交付与源码提供范围遵循适用许可证及合同约定；具有通用价值且具备相应权利的改进，优先回到公开产品。

## 5. Free Software, Paid Services / 软件免费，服务收费

CloudFile's business model centers on professional services: consulting, custom development, implementation, historical data migration, upgrades from Seafile and ongoing technical support. Users may use the open-source software without purchasing services, subject to its licenses. Paid engagements define their scope, acceptance criteria, fees and support commitments separately.

CloudFile 围绕专业服务开展商业化，包括咨询、定制开发、实施部署、历史数据迁移、从 Seafile 升级以及持续技术支持。使用者可以在遵守许可证的前提下使用开源软件，无需购买服务。付费服务另行约定范围、验收标准、费用和支持承诺。

## 6. Sustain The Product And Give Back / 持续发展，回馈上游

Service revenue supports product maintenance, quality improvements and long-term development. CloudFile aims to contribute useful fixes, documentation and general improvements upstream within its capacity, respect upstream maintainers' legitimate interests and avoid unauthorized proprietary code. Cooperation with the open-source ecosystem is a long-term product principle.

服务收入用于支持产品维护、质量提升与长期发展。CloudFile 力所能及地向上游贡献通用修复、文档和改进，尊重上游维护者的正当利益，不主动破坏上游利益，不使用未经授权的专有代码。与开源生态合作是长期产品原则。
